# Безопасный рефакторинг CSS

## Цель

Постепенно сократить `styles.css`, не меняя утверждённый внешний вид и поведение сайта. Старый файл остаётся временной базой, а финальные правила компонентов переносятся в `css/`.

## Главные запреты

- Не удалять селекторы по эвристике «не найден в HTML»: классы дневника, галереи и каталога создаются JavaScript.
- Не запускать массовую замену или удаление `!important`.
- Не форматировать весь `styles.css` одним действием.
- Не переносить компонент без подключения нового файла после `styles.css` и проверки в браузере.
- Не удалять старый CSS до подтверждения, что модуль даёт идентичный результат на всех нужных ширинах.
- Не затрагивать чужие незакоммиченные изображения, скрипты и файлы деплоя.

## Рабочий порядок для каждого компонента

1. Зафиксировать текущее поведение: страница, брейкпоинты, интерактивные сценарии.
2. Выбрать один финальный слой CSS — последний рабочий вариант, а не смесь старых патчей.
3. Перенести его в отдельный файл `css/<component>.css`.
4. Подключить файл **после** `styles.css` только на нужных страницах.
5. Проверить внешний вид и поведение.
6. Удалить из монолита только блок между однозначными комментариями-маркерами.
7. Повторить проверки и только затем переходить к следующему компоненту.

## Очерёдность работ

### 1. Дневник Енота — следующий приоритет

Целевой мобильный вариант: `DIARY: MOBILE HORIZONTAL PAGES`.

- Оставить горизонтальное листание, стрелки, свайп, индикатор активной страницы и закрытие.
- Разобрать старый вертикальный режим отдельно: в нём смешаны старые desktop-правила, поэтому нельзя удалить его большим диапазоном без предварительного переноса нужных desktop-стилей.
- Сначала закрыть и вынести правила desktop-кнопки закрытия, 3D-книги и страниц; потом удалять вертикальные mobile-слои.

### 2. Контактная секция

- Перенести финальный дизайн в `css/contact.css`.
- Подключить на главной и проверить поля, чекбокс согласия, ошибку/успех и плавающий WhatsApp.
- После проверки удалить `CONTACT FORM & SECTION REDESIGN` и лишь затем объединить вертикальные отступы с компонентом.

### 3. Общие компоненты

- Утвердить единые стили кнопок, секционных заголовков, карточек, focus-visible и touch targets в `css/components.css`.
- Не менять палитру или размеры без отдельной UX-задачи.

### 4. Hero и базовые токены

- Вынести в `css/hero.css` и `css/tokens.css` только после того, как завершены зависимые компоненты.
- Проверить, что токены не дублируют или не меняют значения переменных в legacy-файле.

## Проверки после каждого шага

### Визуальные

- Ширины: 390, 768, 1024, 1280/1440 px.
- Нет горизонтальной прокрутки.
- Шапка: desktop — 64 px; mobile — 58 px; кнопка меню скрыта на desktop и минимум 44×44 px на mobile.
- Логотип не перекрывает навигацию и контакты.
- В галерее сохранены бесконечная анимация и пауза при hover/focus.
- В дневнике на телефоне одна страница целиком в видимой области; перелистывание работает в обе стороны.

### Функциональные

- Открыть/закрыть дневник; проверить стрелки, свайп, первую и последнюю страницы.
- Открыть фото в галерее; проверить стрелки, свайп, Escape и закрытие.
- Открыть мобильное меню и перейти по каждой ссылке.
- Проверить форму: обязательные поля, согласие, отправка, отображение ошибки/успеха.
- Пройти интерактивные элементы с клавиатуры: Tab, Enter, Escape, стрелки.

### Технические

```powershell
# Синтаксис и точные дубли (по умолчанию ничего не меняет)
python tools\refactor_css.py styles.css

# Удаление только точных дублей — только после просмотра вывода
python tools\refactor_css.py styles.css --apply-identical

# Просмотр заранее проверенных слоёв
python tools\remove_legacy_css_blocks.py styles.css --list
```

- Убедиться, что баланс `{}` равен нулю.
- Проверить `git diff` только по файлам текущего компонента.
- Не коммитить случайно `images/`, архивы и утилиты деплоя.

## Критерий готовности

Компонент считается отрефакторенным только когда его финальные правила находятся в одном модуле, legacy-блок удалён, все проверки пройдены и число строк/`!important` уменьшилось без визуальной регрессии.
